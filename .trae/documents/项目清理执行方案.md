## 五、安全与风险注意事项

1. **版本兜底**：本次操作全部在 git 仓库内执行，任何误删可 `git show HEAD:<path>` / `git restore` 恢复；`nav-site-dist.zip` 删除前已确认无真实凭据（仅驱动占位符），无泄露风险
2. **删除面确认**：只删 A/B 级列出的文件；`.edgeone/project.json`、`edge-functions/`、`neon_schema.sql`、`package-lock.json`、`contracts.ts` 等 D 级文件**一律不碰**；`src/` 不做任何删除
3. **rest 删除前提**：用户已确认线上 `VITE_BACKEND=neon`（默认值）且无其他服务器运行 `backend-reference` 指向同一 MySQL；如后续发现仍有 rest 使用场景，可从 git 历史找回
4. **bcryptjs 迁移风险**：移入 devDependencies 后，仅 `npm ci --omit=dev` 的生产环境无法执行 README 的哈希生成命令（该命令本就只用于本地初始化，风险可忽略）
5. **提交与推送**：清理完成后提交一个本地 commit 固化结果；**默认不 push**，如需同步远程由用户确认后执行
6. **lockfile 同步失败兜底**：若 `npm install --package-lock-only` 因网络失败，改用 `npm uninstall bcryptjs && npm install -D bcryptjs@^3.0.3`；两者都失败则暂停该步骤并询问，**不得手工改 lockfile**
