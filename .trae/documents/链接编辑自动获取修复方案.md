# 修复链接编辑时"自动获取"无响应问题

## Summary
后台链接管理的添加/编辑共用同一个弹窗与同一个 `autoFetch()` 函数，但 `autoFetch()` 第一行存在 `if (editingLink.value || fetching.value) return` 的编辑态硬拦截，导致编辑已有链接时点击"自动获取"按钮直接返回、无任何反应。移除该拦截，并补充图标覆盖保护，使编辑态与新增态行为一致且安全。

## Current State Analysis
- 文件：[src/views/admin/LinksView.vue](file:///workspace/src/views/admin/LinksView.vue)
- 添加/编辑共用同一弹窗模板（第 86-131 行），"自动获取"按钮事件绑定一致：`@click="autoFetch(true)"`，仅 `:disabled="fetching"`，与编辑态无关。
- 差异点：`autoFetch()`（第 312-351 行）首行 `if (editingLink.value || fetching.value) return`。编辑态时 `editingLink` 已被 `openEdit()` 赋值，因此函数在第一步即返回——这就是"点击无响应"的根因。注释也写明"仅添加模式生效"。
- 函数内其余逻辑（URL 归一化、图标模板拼串、标题 API 请求、`!form.value.title || force` 覆盖判断）均不依赖编辑/新增态，`openEdit()` 已正确回填 `form.url`，移除拦截后即可正常工作。
- 图标填充（第 329-331 行）当前是无条件赋值：编辑态下若仅 blur URL 输入框（force=false）也会覆盖已有自定义图标，需加保护。

## Proposed Changes
全部改动集中在 `src/views/admin/LinksView.vue` 的 `autoFetch()`：

### 1. 移除编辑态拦截
第 314 行：
```ts
if (editingLink.value || fetching.value) return
```
改为：
```ts
if (fetching.value) return
```
按钮点击传 `force=true`，编辑态会按预期覆盖名称与图标；blur 触发时 `force=false`，因 `!form.value.title || force` 条件，已填写的名称不会被覆盖。

### 2. 图标赋值加保护（防编辑态误覆盖）
第 328-332 行，将无条件覆盖图标改为仅在"未填图标或强制获取"时写入：
```ts
// 1. 立即填充图标 URL（未填图标时填充；force 时强制刷新）
if (!form.value.icon || force) {
  form.value.icon = fetchIconApi.value
    .replace(/\{hostname\}/g, hostname)
    .replace(/\{url\}/g, encodeURIComponent(raw))
}
```
说明：新增态图标初始为空，行为与原来完全一致；编辑态 blur 时不再静默冲掉已有自定义图标，点击按钮（force=true）仍可刷新。

### 3. 更新过期注释
第 312 行注释由"仅添加模式生效"改为说明"添加/编辑均生效；编辑时点击按钮强制覆盖名称与图标，blur 仅在名称/图标为空时填充"。

## Assumptions & Decisions
- 编辑态点击"自动获取"按钮应强制覆盖已填写的名称与图标（`force=true` 语义），符合用户"编辑时也能正确自动获取"的预期。
- URL 输入框 blur 时（force=false）仅在名称/图标为空时填充，避免编辑态无意的覆盖。
- 不修改 ApplyView.vue：其为新增申请表单，无编辑态，不受此 bug 影响。

## Verification
1. 构建验证：`npm run build`（含 vue-tsc）通过。
2. 手动验证（浏览器后台→链接管理）：
   - 添加态：输入 URL 后点击"自动获取"，名称与图标正常填充（回归确认不受影响）。
   - 编辑态：打开已有链接，点击"自动获取"，按钮显示"获取中..."，名称与图标按接口返回更新。
   - 编辑态安全：打开已有链接（含自定义图标），仅 blur URL 输入框，自定义图标不被覆盖；点击按钮后图标被刷新。
