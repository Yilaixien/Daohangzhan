# 首页滑动动画低端设备流畅度优化（保持动画效果不变）

## 概述（Summary）

首页滑动相关的动画效果（日期/导航条淡出、搜索胶囊吸顶过渡、返回顶部按钮出现）在低端设备上卡顿。优化目标：**视觉动画效果完全不变**，只替换"滚动事件如何驱动状态"的机制，消除每帧强制布局读取与多余的滚动监听、减少滚动时的不必要绘制，从而恢复低端设备上的滑动流畅度。

## 现状分析（Current State）

首页共 3 处 scroll 监听与状态切换：

| 位置                                                   | 现状                                                                                         | 问题                                      |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------ | --------------------------------------- |
| `src/views/frontend/HomeView.vue`（L106-124）          | 已用 `ticking + requestAnimationFrame` 节流，但每帧仍调用 `shellRef.getBoundingClientRect().top` 判断吸顶 | **每帧强制同步布局读取**，打断浏览器增量布局；滚动期间是最大的主线程开销  |
| `src/views/frontend/FrontendLayout.vue`（L67-69, L72） | `window.scrollY > 64` 直接写 `navHidden`，**未节流**                                              | 每个 scroll 事件（60\~120Hz）都触发响应式写入 + 类名重渲染 |
| `src/components/frontend/BackToTop.vue`（L21-23, L30） | `window.scrollY > 300` 直接写 `visible`，**未节流**                                               | 同上                                      |

其他放大卡顿的因素：

- 吸顶搜索区 `.search-glass`（[style.css](file:///workspace/src/style.css#L161-L167)）带 `backdrop-filter: blur(30px)`，内容滚过时每帧重算背景模糊——低端 GPU/CPU 的主要成本，且无可避免（保留效果）。

- `.search-shell`（[HomeView.vue](file:///workspace/src/views/frontend/HomeView.vue#L127-L140)）已 `transform: translateZ(0)` 提升合成层，但 `will-change: transform, max-width` 中的 `max-width` 不可合成、无意义，应去掉。

- 分组的分类区块（L59-75）整批渲染在滚动区，屏幕外的卡片也要参与绘制与 blur 采样。

- 既有的一次性过渡（max-width 拉伸、chips 的 max-height 收起、date/导航的 opacity+transform 淡出）多为合成器友好属性，且仅在吸顶阈值翻转瞬间触发 1 次，**保留不动**（改它们会改变观感且收益低）。

## 变更方案（Proposed Changes）

### 1. 新增共享滚动源 `src/composables/useScroll.ts`（核心）

把 3 个独立监听收敛为**模块级单例的 1 个被动滚动监听**，内部用 `requestAnimationFrame` 节流，发布响应式 `scrollY`：

- 模块级 `scrollY: Ref<number>`，首个组件 `onMounted` 时惰性初始化（补读当前 `window.scrollY`），之后所有消费者复用同一监听。

- 滚动回调：`ticking` 防重入 → `rAF` 内写 `scrollY.value = window.scrollY`，帧末再补一针 rAF 复位（消除滞后）。

- `onUnmounted` 不注销监听（SPA 内仍在使用；避免组件间卸载竞争）。

- 暴露 `{ scrollY }`。

消费方式：各组件用 `const { scrollY } = useScroll()`，再以 `computed` 派生布尔态——`scrollY` 每帧更新，但 computed 值不变时不触发模板重渲染，开销降至最低，且**彻底不在滚动路径里读布局**。

### 2. `src/views/frontend/HomeView.vue` —— 吸顶判定改为「缓存阈值 + computed」

- 删除 `handleScroll` / `ticking` / 窗口 scroll 监听（L106-124）。

- 新增 `stuckAt = ref(0)` 与 `measure()`：在 `onMounted`（`store.fetchData()` 完成后）与 `window resize` 时执行一次 `shellRef.getBoundingClientRect().top`（滚动位置为 0 时即起始偏移）。**只在挂载/缩放时读布局，不在滚动帧内读**。

- `const scrolled = computed(() => scrollY.value >= stuckAt.value)`：sticky `top:0` 元素在 `scrollY >= 起始偏移` 时恰好触顶，与原判定（`rect.top <= 0`）等价，视觉切换点完全一致。

- 移除组件自身的 `window.addEventListener('scroll')`。

### 3. `src/views/frontend/FrontendLayout.vue` —— 导航条隐藏改为 computed

- 删除 `handleScroll` 与窗口监听（L67-69, L72, L86-88）。

- `const navHidden = computed(() => scrollY.value > 64)`，模板、过渡样式（`transform: translateY(-150%)` / opacity 淡出）一律不动。

### 4. `src/components/frontend/BackToTop.vue` —— 出现逻辑改为 computed

- 删除 `handleScroll` 与窗口监听（L21-23, L29-35）。

- `const visible = computed(() => scrollY.value > 300)`，`v-show` + `Transition` 淡入淡出不动。

### 5. `HomeView.vue` 样式微调（零观感变化）

- `.search-shell`：`will-change: transform, max-width` → `will-change: transform`（去掉不可合成的 max-width），追加 `contain: paint`（隔离内部绘制，避免溢出重绘）。

- 分组卡片区域 `<section v-for>`（L59）：追加 `content-visibility: auto` + `contain-intrinsic-size: auto 360px`，滚动时跳过屏幕外分组的渲染/绘制，直接削减低端机的绘制面与 backdrop-filter 采样负荷；不支持的旧浏览器自动忽略（渐进增强）。加载骨架屏区同理追加（可选项）。

- 全部过渡时长、缓动、backdrop-filter 数值不做任何修改。

## 假设与决策（Assumptions & Decisions）

- **效果零改动**：动画触发的"时刻"（吸顶/隐藏阈值）与"过程"（时长/缓动/透明度）均与原实现一致；仅替换状态计算与事件驱动方式。

- 玻璃模糊数值（blur 30px / 90px 等）不改——任何模糊半径调整都会改变观感，用户明确要求保持原效果。

- 一次性过渡（max-width 拉伸、chips max-height 收起）保留原样：它们只在阈值翻转瞬间执行一次且区域小，优化收益低、改动风险高。

- `useScroll` 不做主动注销，避免 SPA 中多组件生命周期竞争；页面常驻（app 级布局）无内存泄漏问题。

- 仅涉及首页（前台）；管理端无此类滑动动画，不触碰。

## 验证（Verification）

1. `npm run build`（vue-tsc 类型检查 + vite build + edge-functions 打包）通过，无类型/引用错误。
2. `npm run dev` 手动验证：

   - 下拉首屏：日期时间淡出、导航胶囊上移淡出、搜索胶囊吸顶拉伸至通栏、吸顶小时间淡入、chips 收起 —— 观感与改动前一致；

   - 上滑回顶：各元素按原阈值/动画恢复；

   - 返回顶部按钮在 scrollY > 300 出现。
3. 性能验证（低端模拟）：DevTools Performance / CPU 6x 降速录制滚动区间，确认无连续强制布局（long layout 块）、主线程长任务明显减少；滚动期间 FPS 更稳。
4. 窗口缩放时吸顶阈值随 `measure()` 重新计算，无错位。
