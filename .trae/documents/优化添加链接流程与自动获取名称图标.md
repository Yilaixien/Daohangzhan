# 优化添加链接流程：URL 优先 + 自动获取名称与图标

## 概述 Summary

优化后台「链接管理 → 添加链接」弹窗流程：
1. **调整字段顺序**：URL 放在第一位，名称放在第二位（现为名称在前）。
2. **自动获取名称**：输入链接（失焦或点击按钮）后，调用 `https://lianjie.hjke.cn/api/title?url=<编码后的链接>` 获取网页标题并自动填充「名称」。
3. **自动填充图标 URL**：按格式 `https://a.favicon.im/<完整域名>`（如 `https://a.favicon.im/www.zhihu.com`）自动填充「图标 URL」。
4. **触发范围**：仅「添加链接」时触发；「编辑链接」不触发自动获取（用户已确认）。

## 拟改动 Proposed Changes

**仅改一个文件**：`src/views/admin/LinksView.vue`

### 1. 模板：调整字段顺序 + URL 输入框增强

- 在添加/编辑弹窗表单内（[第 90-97 行附近](file:///workspace/src/views/admin/LinksView.vue#L90-L97)），把「URL *」字段移到「名称 *」之前。
- URL 输入框：
  - 加 `@blur="autoFetch"`（失焦自动获取）。
  - 输入框右侧加「自动获取」按钮（仿 ApplyView 的 `flex gap-2` 布局），`type="button"`，`@click="autoFetch(true)"`，`disabled` 状态绑定 `fetching`，文案 `fetching ? '获取中...' : '自动获取'`。
- 名称输入框加 `placeholder="输入链接后自动获取"`，并加一个 `v-if="fetching"` 的小字提示「正在获取名称...」（可选，保持轻量）。

### 2. 脚本：新增状态与 autoFetch 逻辑

- 新增状态（放 `showCheckResult` refs 附近）：
  ```ts
  const fetching = ref(false) // 正在自动获取名称/图标
  ```
- 新增函数：
  ```ts
  async function autoFetch(force = false) {
    // 仅添加模式触发；编辑时不自动获取
    if (editingLink.value || fetching.value) return
    let raw = form.value.url.trim()
    if (!raw) return
    if (!raw.startsWith('http://') && !raw.startsWith('https://')) {
      raw = 'https://' + raw
      form.value.url = raw
    }
    let hostname = ''
    try {
      hostname = new URL(raw).hostname
    } catch {
      return // URL 非法时静默放弃
    }

    // 1. 立即填充图标 URL（纯前端拼串，无需网络检查）
    form.value.icon = `https://a.favicon.im/${hostname}`

    fetching.value = true
    try {
      // 2. 请求标题 API 获取名称
      const resp = await fetch(`https://lianjie.hjke.cn/api/title?url=${encodeURIComponent(raw)}`)
      if (!resp.ok) throw new Error('request failed')
      const json = await resp.json()
      const name = json?.data?.title as string | undefined
      if (name) {
        // blur 触发时不覆盖用户已填名称；手动按钮强制覆盖
        if (!form.value.title || force) form.value.title = name.trim()
      }
    } catch {
      // 获取失败静默处理：名称留空由用户手填，不影响保存
    } finally {
      fetching.value = false
    }
  }
  ```
- `openAdd()` 无需改动（已重置 form）。

### 3. 明确不改的部分

- `openEdit()` 及编辑模式：不动，不触发自动获取。
- 批量添加弹窗：不动（保持现有「名称 | URL | 分组ID」格式）。
- 服务层契约（contracts.ts）、Supabase/REST 实现：均不动，纯前端交互优化，不涉及数据存储变更。

## 假设与决策 Assumptions & Decisions

- **部署环境**：EdgeOne Pages 纯静态前端 + Supabase 后端，无自建代理；标题获取直接使用用户指定的第三方 API `lianjie.hjke.cn`（前端 fetch，依赖其 CORS 配置；实测响应正常）。
- **图标 URL 格式**：`https://a.favicon.im/<完整 hostname>`（保留 `www.`，与用户示例 `https://a.favicon.im/www.zhihu.com` 一致）。
- **名称填充策略**：失焦触发时仅在名称为空时填充（不覆盖用户已输入内容）；点「自动获取」按钮时强制覆盖。均仅在添加模式生效。
- **失败处理**：标题 API 失败/超时时静默放弃（名称留空手填），图标 URL 不依赖网络请求直接生成；不做重试、不做加载失败报错弹窗，避免过度设计。
- **URL 规范化**：沿用 ApplyView 的规则，无协议前缀时自动补 `https://`，并用 `new URL` 校验合法性；非法 URL 静默放弃自动获取。
- **触发时机**：仅 URL 输入框 blur 和「自动获取」按钮两种入口；图标/名称不在每次按键时请求（避免频繁请求）。

## 验证 Verification

1. **构建**：`npm run build` 通过（vue-tsc 无类型错误）。
2. **手动验证（`npm run dev`，进 `#/admin` 链接管理）**：
   - 点「添加链接」，确认弹窗内 **URL 在第一行**、名称为第二行。
   - 填入 `https://www.zhihu.com` 后失焦：
     - 名称自动填充为「知乎 - 有问题，就会有答案」；
     - 图标 URL 自动填充为 `https://a.favicon.im/www.zhihu.com`，可在预览/保存后列表显示图标。
   - 填 `www.baidu.com`（无协议前缀）：确认自动补全为 `https://www.baidu.com` 且名称、图标均自动填充。
   - 标题 API 抓不到的站点（或断网）：名称留空不报错，图标 URL 仍正常填充，表单可正常保存。
   - 先手填名称再失焦 URL：名称不被覆盖；点「自动获取」按钮：名称被 API 结果覆盖。
   - 「编辑链接」弹窗：字段顺序同样为 URL 在前；失焦 URL、点击按钮均**不**触发自动获取，已有名称/图标不被修改。
3. **回归**：添加/编辑保存、批量添加、删除、死链检测等其他功能不受影响。
