# 导航栏首屏透明化与部署产物同步方案

## 概要（Summary）

用户反馈：线上站点**首次打开时导航栏呈现磨砂（毛玻璃）质感，一旦滚动就切换为透明/消失**，存在透明度突变的跳变感。目标：导航栏从首屏加载起就保持透明样式，任何时刻都不出现"先磨砂、后透明"的跳变，并核对相关样式类与滚动监听逻辑。

排查结论：**该现象只存在于旧的线上部署产物（`nav-site-dist.zip`，09-03 构建）中**；当前源码（`src/`）已在此前 [首页导航与日期时间简改方案](首页导航与日期时间简改方案.md) 中把磨砂导航胶囊彻底移除，导航栏现在是无背景、无滚动切换的普通文字行。因此本方案的核心动作是：**用当前源码重新构建生产产物，并刷新被跟踪的部署存档** **`nav-site-dist.zip`，使线上与源码一致**；源码层面经复核**无需改动**（改动即伪造，不予执行）。

## 现状分析（Current State）

### 用户看到的（线上部署产物 = 旧构建）

`nav-site-dist.zip` 内仍是旧版前端（解包核对过 `assets/FrontendLayout-*.js` 与 `.css`）：

- 导航栏为 `<header class="fixed top-4 left-4 z-40 glass rounded-full transition-all duration-500">` 悬浮玻璃胶囊（`backdrop-filter` 毛玻璃）。

- 滚动逻辑：`window.addEventListener('scroll', () => navHidden = window.scrollY > 64)`，命中后挂 `.nav-hidden` → `opacity: 0; transform: translateY(-150%)`（即"滚动后透明/消失"）。

- 旧首页同时带吸顶搜索、日期时间淡出等滚动行为（与本次无关）。

- 旧构建在**挂载时不读取当前滚动位置**，仅在"下一次滚动事件"才纠正状态——刷新时若浏览器恢复滚动位置≥64px，会先闪磨砂胶囊再跳变，正是"突然跳变"的直接来源。

### 当前源码（应作为线上基准）

- [FrontendLayout.vue](file:///workspace/src/views/frontend/FrontendLayout.vue#L8-L23)：导航为 `main` 内流式普通行（`px-4 sm:px-6 pt-6 pb-3 flex`），链接仅用 `glass-text`（白字+投影），**无背景、无边框、无模糊、无 fixed、无滚动绑定**；组件无 `<style>` 块。

- [useScroll.ts](file:///workspace/src/composables/useScroll.ts#L48-L60)：共享单例滚动源，**挂载时补读** **`window.scrollY`**（避免"恢复滚动位置后首次滚动才纠正"的 bug 模式）；当前唯一消费者是 [BackToTop.vue](file:///workspace/src/components/frontend/BackToTop.vue#L18-L23)（`scrollY > 300` 显示），与导航无关联。

- [style.css](file:///workspace/src/style.css)：已对全文件 grep `nav|header`，无任何导航相关规则；`.nav-hidden` / `.pill-link` 等旧类只存在于旧产物打包后的 CSS 中。

- 全局降级机制（`html[data-scrolling]` 滚动中关模糊、`html[data-low-end]` 低配静态降级）不涉及导航栏样式。

### 关键差异结论

| 项        | 线上旧构建（`nav-site-dist.zip`） | 当前源码              |
| -------- | -------------------------- | ----------------- |
| 导航形态     | `fixed` 悬浮玻璃胶囊             | 流式普通文字行           |
| 初始状态     | 毛玻璃（可见）                    | 透明（无背景）           |
| 滚动后      | `opacity:0` 上移消失           | 仅随页面自然滚动          |
| 初始化读滚动位置 | 无（导致跳变）                    | 有（useScroll 挂载补读） |

## 变更方案（Proposed Changes）

### 1. 【核心】用当前源码重建生产产物并刷新部署存档

- 执行 `npm run build`（package.json 脚本：`npm ci` 全新依赖 → `vue-tsc -b` 类型检查 → `vite build` → 拷入并 esbuild 打包 `edge-functions`），产物生成于 `dist/`（已 gitignore）。

- 用新 `dist/` 重新打包部署存档，覆盖旧的 `nav-site-dist.zip`（保持原目录结构：`index.html` + `assets/` + `edge-functions/`）：

  ```bash
  cd dist && rm -rf ../nav-site-dist.zip && zip -qr ../nav-site-dist.zip .
  ```

- 目的：仓库内被跟踪的部署产物不再携带旧版磨砂导航，线上重新部署后即得到"首屏透明、全程无跳变"的效果。

### 2. 【复核】源码与样式/滚动监听核对（只读检查，结论已确认，不改动）

- [FrontendLayout.vue](file:///workspace/src/views/frontend/FrontendLayout.vue#L8-L23)：确认导航行无任何 `glass`/`btn-glass`/`rounded-full` 背景类、无 `:class` 滚动绑定 → **无磨砂初始化，无需修改**。

- [useScroll.ts](file:///workspace/src/composables/useScroll.ts#L49-L59)：确认挂载即补读 `scrollY` → 已规避"初始化状态与滚动后状态不一致"的跳变根因 → 保持不变。

- [style.css](file:///workspace/src/style.css)：确认无导航相关规则残留 → 保持不变。

- 若在重建后的 `dist/` 中 grep 旧特征（见验证第 2 条）有意外命中，则以删除对应残留类/代码为仅有的兜底修改项。

### 3. 【可选，需用户侧操作】线上部署

- 本沙箱未安装 `edgeone` CLI 且无登录态，无法代为推送 Makers 项目（`daohang2` / `makers-whxtlsb9jkb3`）。

- 可在本机执行 `edgeone makers deploy ./dist`（或控制台上传新 `dist/`/新 `nav-site-dist.zip`）完成上线；部署后复测首页首屏。

## 假设与决策（Assumptions & Decisions）

- 用户所见的"首屏磨砂→滚动后透明"确认为**线上旧构建产物**所致（用户已确认现象环境为线上部署站点）。

- 当前源码已经实现用户期望的"首屏透明、无跳变"，因此**不对源码做无意义改动**；只对齐部署产物。若用户此后仍希望导航保留"滚动后隐藏"的旧体验（仅去掉初始化磨砂），不属于当前设计语境，需另立方案。

- 除导航栏外，搜索胶囊、日期时间、返回顶部等毛玻璃区域均为既定设计，本次不动。

- `.trae-html-share-packages/index.html.zip`（分享预览桩，指向当前 `/src/main.ts`）与本次现象无关，保持不变。

## 验证（Verification）

1. `npm run build` 全流程通过（vue-tsc 类型检查 + vite build + edge-functions 打包无报错）。
2. 构建产物核对：

   - 在 `dist/` 与新建的 `nav-site-dist.zip` 内 grep，确认 **无** `nav-hidden`、`glass rounded-full` 悬浮胶囊、`translateY(-150%)` 等旧特征；

   - 确认 `assets/FrontendLayout-*.js` 包含新的流式导航行（`pt-6 pb-3 flex`），且无 `scrollY > 64` 类导航状态写回。
3. 本地 `npm run dev`（或 `vite preview`）手测：

   - 首屏：顶部导航为透明普通文字行，无毛玻璃背景；

   - 滚动全程：导航无透明度/样式跳变，随页面自然滚动；返回顶部按钮逻辑不受影响；

   - 页面刷新并恢复滚动位置（含非顶部），导航初始状态依然透明，不会先闪磨砂再跳变。
4. 部署后（用户侧 `edgeone makers deploy ./dist`）在线上复测第 3 条。
