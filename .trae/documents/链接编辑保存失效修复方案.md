# 修复「编辑链接页面无法保存编辑内容」问题

## Summary

链接管理后台（`LinksView.vue`）中，添加/编辑共用一个弹窗与同一个 `saveLink()`。经全链路排查（表单数据收集 → 保存按钮绑定 → 前端服务调用 → Edge Function 后端接口 → 错误处理），定位到两个直接导致「无法保存且无任何提示」的缺陷：

1. **表单数据收集缺陷（直接根因）**：`sort_order` 输入框使用裸 `v-model`（未加 `.number`），Vue 3 中 number 输入框绑定的是字符串；用户一旦清空或输入非数字内容，`form.sort_order` 变成 `''`，被原样提交到后端 `UPDATE links SET sort_order = $n` → PostgreSQL 抛 `invalid input syntax for type integer` → 500（前端自动重试 3 次后仍失败）。
2. **错误处理缺陷（系统性）**：`saveLink()` 的 `catch {}` 静默吞掉所有异常，任何失败（上述 500、令牌过期 401、EdgeOne 545、网络波动）都不向用户展示任何信息，表现为「点保存没反应、编辑内容不生效」。

保存按钮事件绑定、后端 `PUT /api/links/:id` 路由与白名单更新逻辑经核查均正确，无需改动。

### 根因 1：`sort_order` 类型漂移（数据收集缺陷）

- [LinksView.vue L121](file:///workspace/src/views/admin/LinksView.vue#L121)：`<input v-model="form.sort_order" type="number">` 未使用 `v-model.number` 修饰符。Vue 3 对 number 输入框默认绑定**字符串**；清空输入框时绑定值为 `''`，输入非法内容时同理。
- [LinksView.vue L365](file:///workspace/src/views/admin/LinksView.vue#L365)：`saveLink` 将 `form.value.sort_order` 原样放入请求体。
- 后端 `updateByWhitelist` 将 body 值直接填入 `sort_order = $n`（无任何类型校验）。
- 结果：`''` 传入 PostgreSQL integer 列 → 数据库报错 → 接口返回 500 → [doApiFetch L91-96](file:///workspace/src/services/neon/index.ts#L91-L96) 视为瞬时故障重试 3 次 → 仍失败。
- 触发场景：编辑链接时改动/清空「排序值」字段后点击保存（用户每改必踩）；未改动该字段时 `sort_order` 保持 `openEdit` 预填的数字，不受影响。

### 根因 2：错误被静默吞掉（错误处理缺陷）

- [LinksView.vue L379](file:///workspace/src/views/admin/LinksView.vue#L379)：`} catch {} finally {` —— 异常被完全丢弃，弹窗不关闭、列表不刷新、无任何提示。这与用户「无法保存编辑内容」的直观体验完全一致。
- 同类静默 catch 还散落在 `loadData` / `autoFetch` / `checkDeadLinks` 等函数中，但本次仅修复保存链路相关的可见性。
- 连带影响：令牌过期时 `doApiFetch` 会静默清 token 并跳转登录页 [neon/index.ts L67-72](file:///workspace/src/services/neon/index.ts#L67-L72)，配合 `catch {}`，用户同样只会感到「保存失败且无解释」。

### 核查结论（无需改动）

- **保存按钮事件绑定**：正确。`@submit.prevent="saveLink"` + `type="submit"` 的提交链路是标准写法。
- **后端保存接口**：`PUT /api/links/:id` 路由匹配（`segments.length === 2`）、白名单字段（`title,url,description,category_id,icon,sort_order,is_visible`）、`RETURNING *`、`{data}` 封装均正确；写成功后 `waitUntil` 重建公开快照 [L671-673](file:///workspace/edge-functions/api/[[default]].js#L671-L673) 也正常。

## Proposed Changes

全部改动集中在 `src/views/admin/LinksView.vue`（最小范围，不触碰后端与其他视图）。

### 1. `saveLink()` 提交数据规范化 + 报错提示（核心修复）

将 [L355-382](file:///workspace/src/views/admin/LinksView.vue#L355-L382) 的 `saveLink()` 改为：构造规范化 `payload`；`sort_order` 强制转为数字并容错（`Number()` 后非法/空值回退 `10`，与新增默认一致）；`category_id` 转 `String` 防类型漂移；出错时 `console.error` 并在弹窗内展示具体错误信息。

```ts
async function saveLink() {
  saving.value = true
  errorMsg.value = ''
  try {
    // number 输入框的 v-model 绑定的是字符串，清空会得到 ''，
    // sort_order 不做归一化会原样入库触发 PostgreSQL integer 类型报错
    const sortOrder = Number(form.value.sort_order)
    const payload = {
      title: form.value.title.trim(),
      url: form.value.url.trim(),
      category_id: String(form.value.category_id),
      icon: form.value.icon?.trim() || null,
      description: form.value.description?.trim() || null,
      sort_order: Number.isFinite(sortOrder) ? sortOrder : 10,
    }
    if (editingLink.value) {
      await services.links.update(editingLink.value.id, payload)
    } else {
      await services.links.create(payload)
    }
    showForm.value = false
    await loadData()
  } catch (error) {
    console.error('保存链接失败:', error)
    errorMsg.value = (error as Error)?.message || '保存失败，请稍后重试'
  } finally {
    saving.value = false
  }
}
```

## Assumptions & Decisions

- 主因判定依据：`sort_order` 空串是该保存链路上唯一能由用户常规操作触发的确定性数据库错误；「无提示」则被 `catch {}` 放大为「完全无法保存」。二者修复后即覆盖用户所述症状。
- 错误提示放在弹窗内（而非全局 toast），改动最小、上下文最清晰；错误文案透传后端 `{message}`（已含如「认证令牌无效或已过期」「缺少环境变量」等可诊断信息）。
- `sort_order` 归一化失败时回退 `10`（与「添加链接」表单默认一致）。
- 范围限定：仅修复链接编辑页保存链路。`CategoriesView.vue` / `SearchEnginesView.vue` 存在同构的 `catch {}` 静默与裸 `v-model` 隐患，与本次任务无关，不改动（可在后续单独处理）。
