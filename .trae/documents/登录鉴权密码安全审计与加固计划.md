# 登录鉴权密码安全审计与加固计划

## 摘要

对登录鉴权链路（前端登录页 → Pinia store → 服务层 → EdgeOne 边缘函数 → Neon 数据库）进行密码/敏感信息处理审计。

**核心结论**：
- ✅ **已使用 bcrypt 哈希**（数据库侧 pgcrypto `crypt()`/`gen_salt('bf',10)`），非明文存储、非明文比对。
- ✅ **不存在明文存储**：`config.admin_pwd` 只存 bcrypt hash，前端/公开快照/RLS 全链路无法读取。
- ✅ **不存在明文传输缺陷**：密码仅在一次 HTTPS POST 中以 `{username, password}` JSON 提交用于校验；校验与加密全部在服务端/数据库侧完成，哈希永不出服务器。
- ⚠️ 发现 6 项风险（P1–P6），本次按用户选定范围实施 **3 项低风险加固**（P1、P4、P5），其余（P2、P3、P6）仅记录结论与整改建议，不实施。

## 一、当前状态分析（审计结论）

### 1.1 密码处理链路全貌

```
LoginView.vue handleLogin()
  → src/stores/auth.ts login()                    前端状态管理
    → src/services/neon/index.ts auth.login()      POST /api/auth/login {username, password}（HTTPS）
      → edge-functions/api/[[default]].js login()  从 config 表取 admin_user/admin_pwd
        → SQL: crypt(明文密码, 存库hash) 比对（Neon pgcrypto，bcrypt）
          → 通过 → 签发 HS256 JWT（7d）→ 返回 { token }
```

### 1.2 已使用 bcrypt 的关键证据（3 处）

| # | 位置 | 逻辑 |
|---|------|------|
| 1 | [\[\[default\]\].js](file:///workspace/edge-functions/api/[[default]].js#L320-L353) `login()` | 登录校验：`SELECT (replace(value,'$2b$','$2a$') = crypt(${password}, replace(value,'$2b$','$2a$'))) AS ok` —— bcrypt 比对在数据库侧完成，明文密码仅作为参数传入 SQL，**不落库、不写日志**。 |
| 2 | [\[\[default\]\].js](file:///workspace/edge-functions/api/[[default]].js#L468-L480) `PUT /api/config/admin_pwd` | 密码写入：`crypt(${value}, gen_salt('bf', 10))` → pgcrypto bcrypt（cost=10，自动加盐），落库的是 hash 而非明文。 |
| 3 | [\[\[default\]\].js](file:///workspace/edge-functions/api/[[default]].js#L44) 注释 + [edge-functions/package.json](file:///workspace/edge-functions/package.json) | 明确「密码校验已改为数据库侧 pgcrypto.crypt，不再依赖 bcryptjs」——即已从早期 JS 端 bcryptjs 方案迁移到 DB 侧方案。 |

### 1.3 无明文存储的关键证据（4 处隔离）

| # | 位置 | 隔离方式 |
|---|------|----------|
| 1 | [\[\[default\]\].js](file:///workspace/edge-functions/api/[[default]].js#L458-L467) `GET /config` | 后台读 config 时 `filter(key !== 'admin_pwd')`；`GET /config/admin_pwd` 直接返回 `null`。 |
| 2 | [\[\[default\]\].js](file:///workspace/edge-functions/api/[[default]].js#L140) `rebuildSnapshot()` | 公开快照 SQL 显式 `WHERE key <> 'admin_pwd'`。 |
| 3 | [neon_schema.sql](file:///workspace/database/neon_schema.sql#L125) RLS 策略 | `rd_config ON config FOR SELECT TO nav_read USING (key NOT IN ('admin_pwd'))` —— 浏览器直连角色在数据库层就取不到。 |
| 4 | [neon_schema.sql](file:///workspace/database/neon_schema.sql#L270) 种子数据 | `admin_pwd` 初始值为空串 `''`（未初始化时为占位，登录校验因 `!adminPwdHash` 直接拒绝，不会用空值当密码）。 |

### 1.4 传输层面的判断

- 登录/改密提交时密码以明文 JSON 经 **HTTPS** 从浏览器传到边缘函数——这是登录校验的**必要步骤**（服务端必须拿到明文才能与 hash 比对），不是缺陷。
- 正确的安全边界是：**只传一次、不落库、不回传、不在客户端只做哈希**。本项目满足前三点；不再做客户端哈希是正确做法（若客户端哈希，则 hash 本身就成了"密码"，反而更危险）。
- 注意：上述安全性依赖站点启用 HTTPS（EdgeOne 默认强制），部署时应确认未关闭。

## 二、发现的安全风险与位置

| 编号 | 风险 | 位置 | 严重度 | 本次处理 |
|------|------|------|--------|----------|
| P1 | **schema 未启用 pgcrypto 扩展**：`crypt()`/`gen_salt()` 依赖 pgcrypto，但 [neon_schema.sql](file:///workspace/database/neon_schema.sql#L18) 只建了 `uuid-ossp`。新环境按此文件初始化后登录/改密会报 `function crypt does not exist` | [neon_schema.sql](file:///workspace/database/neon_schema.sql#L18) | 高（可导致功能不可用/初始化遗漏） | ✅ 实施 |
| P2 | **登录接口无暴力破解防护**：`/api/auth/login` 公网可无限次尝试（仅靠 bcrypt cost=10 抗性） | [\[\[default\]\].js](file:///workspace/edge-functions/api/[[default]].js#L362-L364) | 中 | 仅记录，不实施 |
| P3 | **JWT 存 localStorage 且有效期 7 天**：任意 XSS 可窃取令牌长期复用 | [auth.ts](file:///workspace/src/stores/auth.ts#L6)、[\[\[default\]\].js](file:///workspace/edge-functions/api/[[default]].js#L347-L351) | 中 | 仅记录，不实施 |
| P4 | **审计日志泄露 hash 片段**：`login_probe` 记录 `admin_pwd_prefix: cfg.admin_pwd.slice(0, 4)`（含 bcrypt 版本前缀 `$2b$` 等信息） | [\[\[default\]\].js](file:///workspace/edge-functions/api/[[default]].js#L328-L334) | 低 | ✅ 实施 |
| P5 | **根 package.json 僵尸依赖 bcryptjs@^3.0.3**：Vite 前端与 edge 函数均已不使用（前者无引用，后者改 DB 侧 pgcrypto） | [package.json](file:///workspace/package.json#L26) | 低 | ✅ 实施 |
| P6 | **弱密码无强制校验**：仅文档约定 ≥16 位强密码，UI 与接口均无最小长度限制 | [LoginView.vue](file:///workspace/src/views/admin/LoginView.vue)、[ConfigView.vue](file:///workspace/src/views/admin/ConfigView.vue#L95) | 低 | 仅记录，不实施 |

**补充结论（关于"应如何改用安全的哈希加密方案"）**：当前方案即为正确范式——bcrypt cost=10 + 每密文独立盐（`gen_salt('bf',10)`）+ 密码永不存储/输出 + 校验放数据库侧以规避边缘函数 CPU 200ms 限制（bcryptjs 纯 JS cost≥11 会触达 EdgeOne 单次执行限制报 545）。若未来需更换算法（如 argon2），只需改写入端 `gen_salt` 参数与校验端 `crypt` 调用，并保持"哈希不出服务器"的隔离边界不变。

## 三、拟实施变更（低风险加固）

### Change 1：schema 补齐 pgcrypto 扩展（修复 P1）
- **文件**：[database/neon_schema.sql](file:///workspace/database/neon_schema.sql)
- **改动**：在 L18 `CREATE EXTENSION IF NOT EXISTS "uuid-ossp";` 之后新增一行 `CREATE EXTENSION IF NOT EXISTS "pgcrypto";`（带注释说明用途：bcrypt 加密/校验）：
  ```sql
  -- 启用 UUID 扩展
  CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

  -- 启用 pgcrypto（crypt/gen_salt：管理员密码 bcrypt 加密与登录校验）
  CREATE EXTENSION IF NOT EXISTS "pgcrypto";
  ```
- **为什么**：`crypt()`/`gen_salt('bf',10)` 是 pgcrypto 提供的函数；Neon 支持租户内创建该扩展。补充后可保证新环境按 schema 一次性初始化即可完整可用，消除"函数不存在"隐患。
- **注意**：生产库若已手动 `CREATE EXTENSION pgcrypto` 则幂等无副作用；若未安装，需在已运行库补执行一次（`CREATE EXTENSION IF NOT EXISTS pgcrypto;`），计划内列出该运维步骤。

### Change 2：login_probe 审计日志脱敏（修复 P4）
- **文件**：[edge-functions/api/\[\[default\]\].js](file:///workspace/edge-functions/api/[[default]].js)
- **改动**：L328-334 的 `console.log` 对象中移除 `admin_pwd_prefix` 字段，仅保留 `admin_user_present` / `admin_pwd_empty` 两个布尔与 `username_input`：
  ```js
  console.log(JSON.stringify({
    event: 'login_probe',
    username_input: username || '',
    admin_user_present: cfg.admin_user !== undefined,
    admin_pwd_empty: !cfg.admin_pwd,
  }))
  ```
- **为什么**：`admin_pwd_prefix` 泄露 bcrypt 版本号（`$2b$`）与 hash 前 4 字符，无审计价值却有信息泄露面；布尔字段已足以区分「admin_pwd 缺失/清空」与「密码不匹配」。

### Change 3：移除根 package.json 僵尸依赖 bcryptjs（修复 P5）
- **文件**：[package.json](file:///workspace/package.json)、[package-lock.json](file:///workspace/package-lock.json)
- **改动**：删除 [package.json](file:///workspace/package.json#L26) 中 `"bcryptjs": "^3.0.3"`，然后运行 `npm install` 同步 package-lock.json。
- **为什么**：前端 bundle 与 edge 函数均不再引用 bcryptjs；移除可缩小依赖面与打包体积。README L64 的 `node -e "require('bcryptjs')..."` 只是文档里的本地哈希生成示例命令，保留不动（文档说明该命令需全局/临时安装 bcryptjs，或提示可用在线 bcrypt 生成器代替——本次不改 README，仅做备注）。

## 四、假设与决策

1. 用户选定范围为「审计报告 + 低风险加固」；P2（登录限速）、P3（JWT 有效期/localStorage）、P6（弱密码校验）**不实施**，仅在报告中记录整改建议。
2. 当前生产库已能正常登录（此前文档确认 pgcrypto 认证链路可用），因此 Change 1 对现有库为幂等补充；是否需要我附一条「线上补充执行 `CREATE EXTENSION IF NOT EXISTS pgcrypto;`」的运维提示——以备注形式写入计划，不作为代码产出。
3. bcrypt cost 因子维持 10 不改动（改大会触达边缘函数 CPU 200ms 限制）。
4. README 不改动（其 bcryptjs 引用仅为本地生成 hash 的示例命令，非运行依赖）。
5. 不新增登录限速、JWT httpOnly Cookie 化等结构性改造，避免超出本次选定范围。

3. **依赖变更**：确认根 `package.json` 与 `package-lock.json` 中已无 `bcryptjs`；`npm ls bcryptjs` 返回空；前端 `npm run build` 成功。
4. **回归验证（若有线上环境）**：
   - 旧密码登录成功、错误密码返回 401「用户名或密码错误」；
