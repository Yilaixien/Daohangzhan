# 修复首页背景图片被遮挡方案

## 一、Summary

用户反馈：首页**背景图片（后台配置的 `background` 图片）不显示了**。

根因定位（与最近一次"恢复管理端样式"改动直接相关）：上次为了把玻璃主题作用域化到前台，我给 `FrontendLayout` 根节点加了 `.glass-page` 类，并在 `style.css` 中为 `.glass-page` 设置了**不透明渐变 `background: linear-gradient(160deg, var(--page-bg-1), ...)`**。而首页背景层 `BackgroundImage` 是**父节点内部**的 `fixed inset-0 -z-10` 元素：

- `.glass-page` 根 div（`position: relative; z-index: auto`）**不创建堆叠上下文**，`-z-10` 的 `BackgroundImage` 会上升到根堆叠上下文，按绘制顺序：**负 z-index 子元素先画，其后才画正常流块级父元素自身的背景** → `.glass-page` 的**不透明渐变背景把 `BackgroundImage`（渐变高光 + 背景图）整层盖住**。
- 渐变与本底层同色，视觉上仍是"渐变"，所以此前截图/走查未察觉；但配置的背景**图片**（位于被遮盖层内）从此不显示。

修复方向：**把 `.glass-page` 的 `background`（及 `background-attachment: fixed`）移除**，只保留 `color: var(--glass-text)` 与作用域 `::selection`；让渐变与背景图完全由 `BackgroundImage` 的 `-z-10` 层负责（恢复为改动前的工作状态）。`body` 保持中性（管理端不受影响，维持上次修复的成果）。

## 二、Current State Analysis（现状）

- `src/views/frontend/FrontendLayout.vue`（L2）：根节点 `class="glass-page min-h-screen flex flex-col relative"`，内部第一个子节点即 `<BackgroundImage :bg-url="bgUrl" />`（L4）。
- `src/style.css` `.glass-page`（最近一次改动新增）：
  ```css
  .glass-page {
    color: var(--glass-text);
    background: linear-gradient(160deg, var(--page-bg-1), var(--page-bg-2) 48%, var(--page-bg-3));  /* 不透明，盖住 -z-10 背景层 ← 问题源 */
    background-attachment: fixed;
  }
  .glass-page ::selection { ... }
  ```
- `src/components/frontend/BackgroundImage.vue`：根容器 `fixed inset-0 -z-10 overflow-hidden`，内含①渐变兜底 div ②两个极光高光 ③配置背景图 `v-if="bgUrl"`（`bg-cover bg-center`，`backgroundImage: url(...)`）④有图时深色蒙层。
- 图像数据流未变：`FrontendLayout` 读取 `services.config.getAll()` → `bgUrl.value = config.background` → 传入 `BackgroundImage`。该链路与 main 分支一致，无需改动。

## 三、Proposed Changes（逐文件）

### 1. `src/style.css` — `.glass-page` 去掉不透明背景

将：
```css
.glass-page {
  color: var(--glass-text);
  background: linear-gradient(160deg, var(--page-bg-1), var(--page-bg-2) 48%, var(--page-bg-3));
  background-attachment: fixed;
}
```
改为：
```css
/* 前台页面作用域：仅提供白字 + 作用域选中态；
   渐变与背景图由 BackgroundImage（-z-10）层负责，这里不再铺不透明背景，
   否则会按绘制顺序盖住 -z-10 背景层，导致配置的背景图不显示 */
.glass-page {
  color: var(--glass-text);
}
```
`::selection` 作用域保留不变。其余玻璃工具类、变量体系、`body`（保持中性、与 main 一致）均不动。

### 2. 不动其它文件
- `src/views/frontend/FrontendLayout.vue`：保持 `glass-page` 类（白字继承仍走它）、配置加载、`BackgroundImage` 传参均不变。
- `src/components/frontend/BackgroundImage.vue`：不改（渐变兜底 + 背景图 + 蒙层的结构和层级本就是对的）。
- `src/main.ts`、后台相关：不改（维持管理端已恢复的状态）。
- `body` 保持无背景：避免后台任何透明缝隙露出渐变；前台在 `BackgroundImage` 挂载同一帧即渲染渐变，无可见闪白。

## 四、Assumptions & Decisions（假设与决策）

1. 封面"背景图片不显示"的根因 = `.glass-page` 不透明渐变按绘制顺序覆盖了父内 `-z-10` 的背景层（含图片）；移除 `.glass-page` 背景后恢复，无需改动其它逻辑。
2. 渐变与毛玻璃质感完整保留：全部由 `BackgroundImage` 的底层渐变 + 高光负责（设计如此）。
3. 前台在 SPA 挂载帧内即有背景层，不存在肉眼可见的白屏闪白；不为此在 `body` 上重铺全局渐变（避免影响后台）。
4. 本次仍是纯样式修复，不新增依赖、不改功能与数据流。
