# 首页链接图标背景框初始透明化方案

## Summary

当前首页首屏加载时，链接卡片（`glass-card`，即"链接图标"的背景框）默认带 `backdrop-filter` 模糊，呈现磨砂（毛玻璃）质感；一旦发生滚动，`useScroll` 在 `<html>` 上打 `data-scrolling` 标记，CSS 临时摘除卡片的 `backdrop-filter`，卡片视觉变成"透明"。用户要求：初始（默认）视觉与滚动后一致，首屏加载即保持透明样式，并确保全程无透明度/样式跳变。

方案核心：把"无模糊（透明）"从滚动临时态改为 `.glass-card` 的**默认态**，即直接删除默认规则中的 `backdrop-filter`，并从滚动降级选择器组中移除 `.glass-card`。滚动监听逻辑保持不动（仍服务于其余仍有模糊的玻璃元素）。

## Current State Analysis

- [style.css](file:///workspace/src/style.css#L111-L118)：`.glass-card` 默认规则包含 `backdrop-filter: blur(var(--glass-blur)) saturate(var(--glass-saturate))` —— 这就是首屏磨砂质感的来源。图标区白色圆角底衬（`bg-white shadow-sm`，[LinkCard.vue](file:///workspace/src/components/frontend/LinkCard.vue#L10)）为常驻不透明白底，与滚动无关，不属于本次问题。

- [style.css](file:///workspace/src/style.css#L250-L258)：`html[data-scrolling]` 选择器组在滚动期间对 `.glass` / `.glass-card` / `.glass-strong` / `.glass-strip` / `.glass-chip` / `.btn-glass` / `.search-glass` 统一 `backdrop-filter: none`。`.glass-card` 因此从磨砂↔透明来回切换；滚动停止（150ms 空闲或 scrollend）后 `data-scrolling` 移除，卡片瞬间恢复磨砂 —— 即"跳变"。

- [useScroll.ts](file:///workspace/src/composables/useScroll.ts#L20-L35)：`setScrolling()` 负责切换 `html[data-scrolling]`，机制本身正确，仅 `.glass-card` 不应再参与该降级。

- [LinkCard.vue](file:///workspace/src/components/frontend/LinkCard.vue#L6)：全站唯一使用 `glass-card` 类的位置。

- 其余玻璃元素：`.glass-chip` / `.btn-glass` / `.search-glass`（搜索框与引擎按钮）在滚动期间有"提高底色不透明度 + 去掉模糊"的**刻意设计**（见 [style.css](file:///workspace/src/style.css#L260-L268)，历次方案均保留），与本次"链接图标背景框"诉求无关，保持不变。

## Proposed Changes

### 文件：`src/style.css`

1. **`.glass-card` 默认规则（L111-118）**：删除 `backdrop-filter: blur(var(--glass-blur)) saturate(var(--glass-saturate));` 一行。初始即与滚动后状态一致（半透明底 + 边框 + 阴影，无模糊）。保留 `transition`（仅 background/transform/box-shadow，不涉及 blur，无需改动）。

2. **滚动降级选择器组（L250-258）**：从 `html[data-scrolling]` 的列表中移除 `.glass-card` 一行（摘掉 blur 变为无意义 no-op，删除以免误导）。组内注释（L247-249）同步补充说明：链接卡片默认即无模糊，不参与滚动降级。

3. `html[data-low-end]` 组中 `.glass-card` 的 `backdrop-filter: none`（L285-293）变为 no-op，保留不改（零行为变化，最小 diff）。

### 文件：`src/composables/useScroll.ts`

- **不改**。`data-scrolling` 机制仍需服务 `.glass-chip` / `.btn-glass` / `.search-glass` / `.glass-strong` / `.glass-strip` 等仍带模糊的元素。经检查逻辑正确，无冗余。

### 明确不改动

- **非 `.glass-card` 的玻璃元素**：搜索框（`.search-glass`）、引擎按钮（`.glass-chip`）、搜索按钮（`.btn-glass`）、页脚横条（`.glass-strip`）、骨架占位（`.glass-strong`）——首次加载的磨砂效果是整体玻璃主题的既有设计，不在本次诉求范围。
- **图标区白色圆角底衬**（`bg-white shadow-sm`）：常驻不透明样式，与滚动无关。
- **hover 高亮**：`.glass-card:hover` 仅改 background，不受本次影响。

## Assumptions & Decisions

- "滚动之后的状态" = 当前 `html[data-scrolling]` 下的 `.glass-card` 渲染（无模糊、保留半透明底/边框/阴影）。按用户"与滚动之后的状态一致"执行，即**精确对齐该渲染**，而非彻底去掉边框或背景。
- 诉求对象为链接卡片（`.glass-card`）：它是全站唯一同时满足"首屏磨砂、滚动后透明"描述且具备"链接图标背景框"语义的元素。
- 不做全局"所有玻璃元素默认去模糊"，避免破坏搜索框等既有玻璃设计（历次方案明确保留）。
