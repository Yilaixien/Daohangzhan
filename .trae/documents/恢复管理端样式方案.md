# 恢复管理端为 main 分支样式（玻璃主题作用域化）

## 一、Summary

用户反馈：前端毛玻璃重构没有问题，但**管理页面全乱了**，要求对比 main 分支改回来。

经 `git diff main..HEAD` 定位：管理端自身的视图文件在本次改动中**只有 `src/views/admin/ConfigView.vue`（+11 行，新增前台主题下拉，属既定功能）**；真正影响管理端的是两处**全局副作用**：

1. `src/style.css` 新增的全局 `body { color: var(--glass-text)(白色); background: 深蓝紫渐变; background-attachment: fixed; }`、`html, body { margin: 0; min-height: 100% }`、全局 `::selection { 白底白字 }` —— 这些作用于**整个站点**（含后台），而管理页大部分文案/下拉/表格依赖「继承默认文字颜色」，被强制继承成白色后，在白底卡片上内容不可见/错乱。
2. `src/main.ts` 的主题初始化（`useThemeStore().init()`）仅设置 `data-theme` 属性与 localStorage，对管理端布局无影响（已确认管理端无任何 `--glass-*`/`data-theme` 引用）。

**解决方案**：把玻璃主题的全局副作用**全部作用域化到前台**（在 `FrontendLayout` 根节点加 `.glass-page` 作用域类），`body` 恢复为 main 分支的中性默认。管理端从此与 main 分支行为完全一致；前台视觉不变。

## 二、Current State Analysis（现状，对比 main）

- `src/style.css`（main 为 1 行 `@import "tailwindcss"`，当前 +205 行）：
  - 全局 `html, body { margin: 0; min-height: 100% }`
  - 全局 `body { color: var(--glass-text); background: linear-gradient(160deg,...); background-attachment: fixed; transition: background .5s }` ← **面向全站，是管理端"乱"的主要来源**
  - 全局 `::selection { background: var(--glass-selected); color: var(--glass-text) }`（白底白字，管理端选中文本不可见）
  - 其余 `.glass*/.btn-glass/.search-glass` 等均为 class 级，管理端不使用，零影响。
- `src/views/frontend/FrontendLayout.vue` 根节点：`class="min-h-screen flex flex-col relative"`（无作用域标记），内部 `<BackgroundImage>` 已渲染同款渐变（fixed inset-0 -z-10），因此把 body 渐变挪到前台根节点后视觉无差异、无闪白风险。
- 前台元素白字来源核查：日期/时间/分组标题/引擎按钮/导航链接/回到顶部/空态等均用 `glass-text*` 或显式 `text-white`；只有「搜索」按钮文字依赖 body/根节点**继承色** → `.glass-page` 提供白色继承后无需改动。
- 管理端零 `glass-` 引用（grep 已确认），AdminLayout/LoginView 等均有显式 `text-*` 与全覆盖背景。

## 三、Proposed Changes（逐文件）

### 1. `src/style.css` — 全局副作用作用域化

**删除**（恢复到 main 的中性全局，管理端不再受影响）：
- `html, body { margin: 0; min-height: 100% }`（Tailwind v4 preflight 已默认 margin:0）
- `body { color/background/background-attachment/transition }` 整条
- 全局 `::selection { ... }`

**新增**（前台专用作用域包装类，替代上述全局效果）：
```css
/* 前台页面作用域（仅 FrontendLayout 使用）：提供白字 + 渐变底色兜底 */
.glass-page {
  color: var(--glass-text);
  background: linear-gradient(160deg, var(--page-bg-1), var(--page-bg-2) 48%, var(--page-bg-3));
  background-attachment: fixed;
}

.glass-page ::selection {
  background: var(--glass-selected);
  color: var(--glass-text);
}
```
其余玻璃变量与工具类**保持不变**（class 级、管理端不引用）。

### 2. `src/views/frontend/FrontendLayout.vue` — 前台根节点加作用域

根节点 `class="min-h-screen flex flex-col relative"` → `class="glass-page min-h-screen flex flex-col relative"`。
- 前台（首页/关于/申请收录，均经 FrontendLayout）继续获得白字与渐变兜底，视觉与现在一致；`BackgroundImage` 的 fixed 渐变层不变（同色叠加，无感）。
- 管理端不再经过 FrontendLayout，完全回归 main 的默认外观。

### 3. 明确不改动
- `src/main.ts`：主题初始化仅写 `data-theme` 属性与 localStorage，对管理端布局零影响，保留。
- `src/views/admin/ConfigView.vue`：前台主题下拉为已确认功能，保留。
- 前端其余样式/组件：不动。

## 四、Assumptions & Decisions（假设与决策）

1. 管理端"乱"的根因判定为全局白字继承 + 白底白字选中态 + body 渐变在个别未遮盖处露出；作用域化后管理端与 main 分支行为等价。
2. 前台在 `.glass-page` 提供渐变的根节点背景 + `BackgroundImage` fixed 层双重保障下，首屏渲染效果与改动前一致；不引入额外逻辑。
3. 不做 git 历史改写：本次修复作为新的工作区改动/提交，不删除已有提交。
4. `.trae-html-share-packages/index.html.zip` 为环境产物，不属于本任务，不改动。
