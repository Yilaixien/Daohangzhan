# 链接按钮去磨砂与滚动跳变修复方案

## 概要（Summary）

用户反馈：**链接按钮（首页链接卡片 LinkCard）首次加载时呈现磨砂（毛玻璃）质感，一旦开始滚动就"变透明"，滚动停止后又变回磨砂，存在明显的样式突然跳变。目标：让链接卡片**从首屏加载起始终呈现"半透明无模糊"的透明样式（与滚动中的观感一致），全程不再有任何透明度/样式跳变，并核对相关样式类与滚动监听逻辑。

排查确认：跳变的直接来源是滚动性能优化引入的 `html[data-scrolling] .glass-card { backdrop-filter: none; }` 降级规则——它在滚动期间瞬间关掉卡片模糊，却不像 `.glass-chip` / `.btn-glass` / `.search-glass` 那样做背景补偿，因此滚动时卡片观感骤变、停止后又恢复。修复方式：从根上移除链接卡片的常驻模糊（`blur`/`saturate`），使卡片在任何时刻都呈现同一观感，"滚动降级"对该类不再产生任何可见变化。

## 现状分析（Current State）

### 相关样式与逻辑（全部为当前源码证据）

- [LinkCard.vue](file:///workspace/src/components/frontend/LinkCard.vue#L6)：链接卡片根元素使用 `class="glass-card flex flex-col items-center p-4 group"`，即整套毛玻璃卡片样式。

- [style.css](file:///workspace/src/style.css#L111-L117)：`.glass-card` 基础规则 `background: var(--glass-bg); border: 1px solid var(--glass-border); border-radius: 12px; box-shadow: var(--glass-shadow); backdrop-filter: blur(var(--glass-blur)) saturate(var(--glass-saturate));` —— 磨砂观感的来源。

- [style.css](file:///workspace/src/style.css#L250-L268)：滚动中降级块 `html[data-scrolling] .glass, .glass-card, .glass-strong, .glass-strip, ... { backdrop-filter: none; }`。其中 `.glass-chip`、`.btn-glass`、`.search-glass` 各自补了更高不透明度背景以维持"玻璃感"（`background: rgba(255,255,255,0.22 / 0.34)`），**唯独** **`.glass-card`** **只去模糊、无任何背景补偿**——`--glass-bg`（浅色 0.12 / 深色 0.42）本就极淡，去掉模糊后卡片在滚动瞬间看起来近乎"消失/变透明"，与静止时磨砂观感差异明显。

- [style.css](file:///workspace/src/style.css#L273-L293)：`html[data-low-end]` 低配静态降级（无模糊）。静态、无切换，不产生跳变；未命中低配的机器上才会看到"磨砂↔透明"切换。

- [useScroll.ts](file:///workspace/src/composables/useScroll.ts#L20-L29)：`setScrolling` 以 150ms 空闲计时 + `scrollend` 控制 `html[data-scrolling]` 标记——是滚动期模糊开关的驱动源，逻辑本身正确，**不改动**；跳变根源在于 CSS 对 `.glass-card` 的补偿缺失，而非监听逻辑。

- 补充核实：旧部署存档 `nav-site-dist.zip` 中不含 `data-scrolling` 机制（grep 为 0），说明用户所见的现象来自**包含该优化的当前构建**（新部署 / `npm run dev` / 分享预览），修复点在当前源码。

### 触发链路（一目了然）

```
静止(加载) ── blur(20px) 磨砂卡片
滚动开始 ── html[data-scrolling] → .glass-card { backdrop-filter:none } → 卡片变"透明"
滚动停止(150ms/scrollend) ── 恢复 blur → 卡片又变磨砂   ← 反复跳变，观感突兀
```

## 变更方案（Proposed Changes）

### 1.【核心】`src/style.css`：移除 `.glass-card` 的常驻模糊

将 [.glass-card 基础规则](file:///workspace/src/style.css#L111-L117) 中的 `backdrop-filter: blur(var(--glass-blur)) saturate(var(--glass-saturate));` **整行删除**，其余（`background: var(--glass-bg); border; border-radius; box-shadow`）与 `:hover` 规则（`background: var(--glass-hover)`）一律保留。

- 效果：链接卡片从首屏起即为"半透明底 + 细边框 + 阴影、无模糊"的透明样式，与用户期望的"滚动后状态"一致；滚动期间 `data-scrolling` 规则虽仍对其写 `backdrop-filter: none`，但因基础样式已无模糊，**成为 no-op**，不再产生任何可见切换。

- 影响面：`glass-card` 目前仅 [LinkCard.vue](file:///workspace/src/components/frontend/LinkCard.vue#L6) 一处使用（模板内已核实），改动不波及其它元件；后续若新增卡片类元素，默认也不再带模糊，符合本项目"滚动期间无模糊切换"的一致性原则。

### 2.【复核，不改动】相关样式类与滚动监听逻辑

- `html[data-scrolling]` / `html[data-low-end]` 列表中的 `.glass-card` 条目**保留**（变更 1 后为 no-op，保留可避免未来若复用模糊卡片时遗漏降级；两处无副作用）。

- `useScroll.ts` 的 `setScrolling` 阈值与 `scrollend` 逻辑正确，**不动**。

- 对照 `.glass-chip` / `.btn-glass` / `.search-glass` 的滚动期背景补偿做法：链接卡片选择"彻底无模糊"而非"滚动期加背景补偿"，因为用户明确要求初始即为透明样式，且补偿方案仍需在停止后恢复模糊、依然存在一次观感切换。

### 3.【可选】部署同步

- 本沙箱无 `edgeone` CLI/登录态，线上部署需在用户本机执行 `edgeone makers deploy ./dist`（项目 `daohang2`）。计划内完成 `npm run build` 验证即可，部署动作交由用户决定时机。

## 假设与决策（Assumptions & Decisions）

- 用户所指"链接按钮"= 首页链接卡片（`LinkCard` / `glass-card`），非导航栏；导航栏保持现有透明文字样式不动。

- 期望的终态 = **半透明底 + 无模糊（与滚动中观感一致）**，而非彻底无背景；卡片保留 `--glass-bg` 底色与边框阴影以保证背景复杂时的可读性与边界感。

- 滚动性能优化（滚动期降级 `backdrop-filter`）机制予以保留（它改善跟手度），只是链接卡片不再依赖该机制、从根上无模糊。

- 不扩展改动 `glass-strip`（页脚，滚动期同样去模糊）等其它区域——用户仅提及链接按钮；如后续需要可另案处理。

## 验证（Verification）

1. `npm run build` 通过（vue-tsc 类型检查 + vite build）。
2. 构建产物 `dist/assets/*.css` 中 grep 确认：`.glass-card` 规则已无 `backdrop-filter`。
3. `npm run dev` 手测：

   - 首屏加载：链接卡片为半透明无模糊样式，不呈现磨砂质感；

   - 全程滚动（含快速滚动与停在半途）：卡片外观**无任何透明度/模糊跳变**；

   - 搜索框、引擎胶囊、返回顶部、导航栏等其余区域行为不变；

   - 桌面端滚动停止后卡片不再"恢复磨砂"。
4. 刷新页面恢复滚动位置后复测第 3 条，无变化。
